# Alive 后台世界工作台视觉设计

> 状态：待书面评审（视觉方向已在对话与原型中确认）
>
> 日期：2026-08-31
>
> 关联设计：`docs/superpowers/specs/2026-08-29-content-worlds-design.md`
>
> 本文只定义后台「世界」入口与三个世界编辑工作台的体验、视觉和动效，不包含实现计划或业务代码。

## 1. 背景

Alive 已经拥有日志、片语、影像三个内容世界，但当前后台仍有两套割裂的表达：

- 「世界」页以横向表单行呈现，更像通用设置后台，而不是创作入口。
- 日志、片语与影像编辑区分别演进，公共结构、视觉密度和动作位置不一致。

这使“世界”主要停留在数据字段和路由中，没有成为作者可以感知的创作空间。

## 2. 设计目标

后台应被理解为“一间安静书房里的三张工作台”：

- 「世界」页负责选择工作台，而不是首先暴露配置表单。
- 进入世界后，默认打开该世界最近编辑的内容，形成“回到上次停笔处”的连续感。
- 三个世界共用稳定的内容架、状态栏与交互语言。
- 中央画布根据媒介变化：日志是手稿，片语是便笺，影像是取景框。
- 差异来自内容结构，不来自三套互不相干的主题色。

## 3. 非目标

本轮不做：

- 允许用户自由创建或删除世界。
- 为三个世界建立彼此独立的主题系统。
- 修改公开站点的世界页面。
- 修改 Entry、分类、标签、发布生命周期等后端业务模型。
- 增加循环、漂浮、粒子或装饰性环境动画。
- 把世界首页变成统计 Dashboard。

## 4. 视觉语言

### 4.1 主题与颜色

继续使用 `@alive/theme`，不增加只服务于世界页的固定品牌色。以墨色主题为参考：

| 角色 | 参考值 | 用途 |
| --- | --- | --- |
| 书房底色 | `#f5f6f8` | 页面与工作区背景 |
| 工作台表面 | `#ffffff` | 世界卡片、编辑画布 |
| 凹陷区域 | `#ebedf0` | 内容架、次级区域 |
| 主墨色 | `#17202a` | 标题、主要动作 |
| 次级文字 | `#62718a` | 状态、说明、元数据 |
| Alive 信号色 | `#5e6ad2` | 焦点、页边线、选中状态 |

其他主题继续通过现有语义变量映射。世界身份不能依赖某个固定颜色，否则换主题后会失去一致性。

### 4.2 字体角色

- `ChillKai`：世界名称、内容标题、日志与片语正文。
- 系统无衬线字体：导航、按钮、保存状态、字段标签。
- 等宽字体：slug、字数、资源编号等少量技术信息。

标题字体承担创作气质；控件字体保持清晰与克制。不能把全部后台文字都改成楷体。

### 4.3 几何与层次

- 控件圆角沿用 `12px`，主要表面沿用 `16px`。
- 世界卡片可以使用约 `16–18px` 圆角，但不能继续堆叠通用玻璃卡片。
- 阴影只用于区分真正抬起的工作台、便笺和浮层。
- 页面层次主要通过留白、边线、排版与内容构图建立。

## 5. 「世界」页

### 5.1 页面职责

「世界」页首先是书房门厅，其次才是设置入口。作者在这里回答“我要回到哪张工作台”，而不是“我要修改哪一组配置”。

页面顶部文案：

```text
世界
回到你上次停笔的地方
```

不展示统计大数字、增长信息或装饰性 Hero。

### 5.2 三张工作台

桌面端使用一大两小的非对称排布：

```text
┌──────────────────┬────────────────┐
│                  │ 片语           │
│ 日志             ├────────────────┤
│                  │ 影像           │
└──────────────────┴────────────────┘
```

三者地位平等，但内部构图表达各自媒介：

- 日志卡片：淡页边线、最近编辑标题、少量正文节奏线。
- 片语卡片：一句真实内容居中，减少额外元数据。
- 影像卡片：小型 `16:9` 取景框与最近影像标题。

每张卡片稳定显示：

- 世界名称。
- 已开放、未开放或暂时隐藏状态。
- 最近编辑内容；没有内容时显示相应空状态。
- 内容总数和分类数等低权重概况。
- 主动作“进入日志 / 进入片语 / 进入影像”。
- 次级动作“设置”。

### 5.3 设置

设置不再作为横向表单常驻页面。点击卡片内“设置”后，打开右侧轻量设置面板，保持三张工作台的排布稳定。面板包含：

- 世界状态。
- 导航名称。
- 该世界真正支持的默认浏览方式。
- 状态影响说明。

只有发生修改时才出现高权重的“保存修改”。保存完成后恢复为安静状态，并使用文字确认成功。

### 5.4 进入行为

点击卡片主体或主动作时：

1. 请求该世界最近编辑的一条后台内容；后台列表已按 `updated_at DESC, id DESC` 排序。
2. 有内容时打开该条内容的对应世界编辑器。
3. 没有内容时打开该世界的空白工作台。
4. 空白工作台不立即创建服务端草稿；首次有意义输入后才创建。

请求失败时卡片保留在原页并显示明确的行内错误与“重试”，不能退化为创建新内容。

## 6. 共享世界工作台

### 6.1 固定结构

三个世界共用：

```text
┌ 内容架 ─────────┬ 顶部状态栏 ─────────────────┐
│ 当前世界         │ 世界 / 当前世界   已保存 设置 发布 │
│ 搜索             ├─────────────────────────────┤
│ 最近编辑         │                             │
│ 草稿 / 已发布     │ 当前世界中央画布             │
│                 │                             │
│ 全部 / 分类 / 设置│                             │
└─────────────────┴─────────────────────────────┘
```

- 左侧内容架只显示当前世界的内容与能力。
- 顶栏固定展示当前世界、保存状态与发布动作。
- 设置与发布继续使用现有侧栏式面板，不把元数据重新铺回主画布。
- 进入世界后不常驻其他世界的切换标签；切换世界需要返回「世界」页。

### 6.2 最近编辑

工作台默认打开最近编辑内容，并在内容架中高亮。作者切换内容前必须完成现有自动保存 flush；失败时停留在当前内容并说明原因。

内容架沿用可折叠、可调整宽度的行为。世界改变时，搜索、分类和状态筛选重置为该世界的默认值，不能把日志筛选条件错误带入片语或影像。

### 6.3 路由与编辑器分派

现有内容详情入口必须根据 Entry 的 `world` 分派编辑器，不能让所有 `/entries/:id` 静默落到日志编辑器。

实施时保留现有后台内容地址，并把 `/entries/:id` 的页面组件改为世界编辑器宿主：

- 世界卡片查询到最近内容后仍进入 `/entries/:id`。
- 宿主读取内容详情中的 `world`，再挂载注册表指定的编辑器；这次详情结果直接传给编辑器，不能重复请求同一条内容。
- 新建继续使用当前注册表中的世界新建路由，并从路由参数或注册定义确定世界。
- `WorldWorkspaceLayout` 在世界解析完成后再挂载对应内容架，避免先短暂显示日志目录。
- 注册表声明世界对应的编辑器、创建动作、内容架文案、媒体能力与发布规则。
- 未知世界显示明确错误并记录诊断信息，不能按日志兜底。

本设计不改变公开 URL，也不改变现有后台可收藏的 `/entries/:id` 地址。

## 7. 三种中央画布

### 7.1 日志：手稿

- 保留居中的长文阅读宽度。
- 画布左侧使用一条极淡页边线作为识别元素。
- 标题使用楷体并保持较大字号，正文保持舒适行长和约 `1.9–2` 的中文行高。
- 日期、分类和字数退居辅助位置。
- 不加入仿真横线、纸张纹理或装订孔。

### 7.2 片语：便笺

- 不显示日志式标题和日期输入。
- 片语正文成为首屏唯一主角，居中但保持真实文本选择能力。
- 来源、原作者、可见性和标签收进“补充信息”折叠区。
- 保存状态与发布动作仍位于共用顶栏，不在底部重复一套按钮。
- 发布后在补充信息中提供永久链接和复制动作。
- 便笺感来自集中构图与有限阴影，不使用黄色纸张或图钉装饰。

### 7.3 影像：取景框

- 首屏首先展示明确的 `16:9` 主视频槽位。
- 槽位内部承担选择文件、上传进度、失败、处理中、播放预览与替换状态。
- 标题和说明位于取景框下方；封面、分类、标签和可见性进入设置侧栏。
- 没有已保存 Entry 时，槽位解释“首次有意义输入后创建草稿”，不能只显示不可操作占位框。
- 深色仅限播放器和取景框内部，不能把整个影像工作台变成另一套深色后台。

## 8. GSAP 动效

### 8.1 使用边界

GSAP 只负责需要编排或中断控制的关键转场：

- 世界卡片进入工作台。
- 当前世界内切换内容。
- 协调内容架和中央画布出现顺序。

按钮 hover、按压、输入焦点、保存文字变化等简单反馈继续使用 CSS。

### 8.2 进入世界时间线

总时长约 `440ms`：

1. 其他世界卡片以 `autoAlpha` 淡出并下移 `8–10px`。
2. 当前卡片缩放到约 `1.018`，不使用 `back` 或 `elastic` 回弹。
3. 路由完成后，内容架从 `x: -16px` 进入。
4. 中央画布以 `y: 8–10px` 和 `autoAlpha` 随后进入。

卡片离场使用 `power3.inOut`，内容架与画布进入使用 `power2.out`。使用一个带标签的 `gsap.timeline()`，不能用多个互不关联的 `delay` 拼接。

### 8.3 切换内容

- 当前画布约 `140–160ms` 淡出并轻微下移。
- 新内容约 `220–260ms` 淡入。
- 内容架选中态可以与新画布同时更新。
- 自动保存或加载失败时不播放离场动画。

### 8.4 Vue 生命周期与性能

- 动画只在 `onMounted` 后创建。
- 每个组件使用根元素作用域与 `gsap.context()`。
- `onUnmounted` 调用 `context.revert()`；进行中的 timeline 必须可被 kill。
- 优先动画 `x`、`y`、`scale` 和 `autoAlpha`，避免逐帧修改宽高、边距和定位。
- `will-change` 只施加给实际参与转场的元素，并在转场结束后清理。
- 不引入 ScrollTrigger、持续监听鼠标位置或循环动画。

### 8.5 减少动态效果

`prefers-reduced-motion: reduce` 下：

- 取消位移、缩放和 stagger。
- 路由和内容切换立即完成，最多保留极短淡入。
- 动画绝不能是理解保存、发布或错误状态的唯一方式。

## 9. 响应式行为

### 9.1 世界页

- 桌面端使用一大两小布局。
- 窄屏改为日志、片语、影像纵向排列，保持固定顺序。
- 三张卡仍通过内容构图区分，不强行保持桌面高度比例。
- 整张卡可点击，但设置按钮必须是独立可聚焦操作，不能触发进入世界。

### 9.2 编辑工作台

- `48rem` 以下沿用现有规则：内容架变成抽屉，中央画布占满屏幕。
- 顶栏常驻返回、保存状态和发布；设置、归档、删除等次级动作收进菜单。
- 日志页边线向屏幕边缘收紧，正文仍保留安全内边距。
- 片语取消大面积悬浮阴影，避免看起来像模态框。
- 影像取景框保持 `16:9`，标题和说明自然排列在下方。
- 所有触控目标不小于约 `44px`。

## 10. 状态与文案

### 10.1 世界状态

- 已开放：前台可见并允许公开发布。
- 未开放：可保存草稿，公开发布前需要开放。
- 暂时隐藏：不出现在前台导航，现有链接仍可访问。

状态必须同时使用文字，不能只使用彩色圆点。

### 10.2 空状态

- 日志：`还没有日志。写下第一篇。`
- 片语：`还没有片语。先记下一句话。`
- 影像：`还没有影像。选择一段视频开始。`

空状态的主动作进入客户端空白工作台，不立即产生服务端记录。

### 10.3 加载与错误

- 卡片概况加载时保留稳定骨架，避免三张工作台跳动重排。
- 某个世界概况失败不能阻塞其他世界。
- 最近内容加载失败时显示“无法打开最近内容”和“重试”，不能自动创建新草稿。
- 409、自动保存失败和发布阻塞继续沿用现有明确文字与恢复路径。

## 11. 组件边界

实施按以下职责拆分，而不是继续扩大单个页面组件：

- `WorldDeskCard`：世界身份、最近内容、概况、进入与设置入口。
- `WorldSettingsPanel`：世界配置、dirty 状态和 revision 冲突处理。
- `WorldWorkspaceLayout`：当前世界内容架、顶栏与中央编辑器插槽。
- `WorldDirectory`：按世界搜索、筛选与最近内容；复用现有目录能力。
- `WorldEditorHost`：根据注册表分派日志、片语或影像编辑器。
- 各世界编辑器：只负责自己的中央画布与专属字段。
- `useWorldTransition`：封装 GSAP timeline、路由协调、减少动态效果和清理。

世界能力与文案仍从一个明确注册表读取，不能在页面模板里散落 `world === 'saying'` 分支。

## 12. 验收标准

1. 「世界」页第一视觉是三张可进入的工作台，而不是三行表单。
2. 点击世界默认打开该世界最近编辑内容；没有内容时打开不落库的空白工作台。
3. 日志、片语、影像共用内容架和顶栏，但中央画布分别呈现手稿、便笺和取景框。
4. 已存在内容始终根据自身世界进入正确编辑器。
5. 三个世界的设置仍可完成，dirty、保存成功和 revision 冲突均有明确反馈。
6. 世界进入与内容切换使用受控 GSAP timeline，卸载后没有残留样式或 tween。
7. `prefers-reduced-motion` 下所有关键流程仍可完整操作。
8. 桌面与 `375px` 视口均能完成进入世界、选择内容、编辑、设置和发布。
9. 键盘可以聚焦整张卡的进入动作与独立设置动作，焦点顺序与视觉顺序一致。
10. 原有自动保存、冲突恢复、发布检查、分类与标签能力不因视觉重构退化。

## 13. 设计自检

- 没有使用暖米色、陶土色、高对比衬线 Hero 等通用编辑产品模板。
- 没有给三个世界硬套三种强调色。
- 唯一明显视觉风险集中在“三张工作台”的媒介构图；其他表面保持克制。
- 动效只服务于“从门厅回到书桌”的空间连续性。
- 结构与既有“沉浸画布 + 可折叠内容目录”方向一致，没有重新引入企业 CMS 壳层。
