# Alive 后台沉浸式文章发布体验设计

日期：2026-08-26  
状态：已确认，待实施规划

## 1. 背景

Alive 后台目前使用 Vue 3、Vite、Milkdown 和自定义 CSS，没有引入完整 UI 套件。现有文章编辑页已经接通标题、slug、摘要、正文、封面 URL、分类、内容类型、发生时间、可见性、保存、发布、撤回、归档和删除，但整体仍是传统长表单。

后台只服务站主本人。目标不是建设多人 CMS，而是建设一个安静、长期使用、不会丢稿的个人写作台。写作体验优先于管理密度，界面风格优先于组件开发速度。

## 2. 目标

1. 让写作成为后台的主界面，而不是表单中的一个字段。
2. 用文章目录支持持续工作，降低在列表页和编辑页之间往返的成本。
3. 默认自动保存，并在离线、失败、刷新和多标签冲突时保护内容。
4. 让编辑画布尽量接近前台文章的主题与排版，同时保持后台控件清晰。
5. 将主题升级为后台与前台共享的站点视觉配置，并保留访客本地偏好。
6. 提供轻量、明确的预览与发布检查，不引入定时发布和多人审核流程。
7. 支持图片粘贴、拖放、上传与当前文章内复用，不提前建设完整媒体库。

## 3. 非目标

- 多人协作、评论、审核、权限流和编辑锁。
- 定时发布、发布任务调度和失败重试队列。
- 完整数字资产管理、全站媒体搜索、重复检测和未引用文件清理。
- 在手机上提供与桌面完全相同的复杂长文组织能力。
- 引入 Element Plus、Ant Design Vue 等接管整体视觉的 UI 套件。
- 本轮设计阶段不修改功能代码。

## 4. 产品方向

### 4.1 视觉论点

Alive 后台是一张可以长期停留的现代纸本写作台。正文由主题决定气质，界面控件使用克制的中性规则，层级依靠排版、留白、表面明度和细线建立，不使用卡片堆叠和装饰性阴影制造“后台感”。

### 4.2 内容结构

后台采用持续存在的应用工作区：左侧文章目录负责定位文章，中央画布负责写作，右侧抽屉负责文章设置与发布检查。写作时没有 Dashboard、长表单和常驻大工具栏打断注意力。

### 4.3 交互论点

- 输入 `/` 时，插入菜单从当前行展开。
- 选中文字时才出现浮动工具条。
- 停止输入后自动保存，顶部只显示真实保存状态。
- 左侧文章目录可一键收起，收起后画布自动居中。
- 主题点击只预览，明确保存后才改变前台默认主题。

## 5. 信息架构与页面布局

### 5.1 左侧文章目录

文章目录参考 Codex 会话目录的工作方式，而不是文章内部的标题大纲。

目录从上到下包含：

1. Alive 标识与收起按钮。
2. 新建文章。
3. 文章搜索。
4. 最近文章，显示标题、最近编辑时间和状态。
5. 文章库分组：草稿、已发布、已归档。
6. 站点主题与站点设置入口。

当前文章使用主题化选中背景和文字色。未同步文章显示小圆点。点击文章时切换中央画布，不再先进入文章管理列表。

第一版不将分类展示成文件树。分类是文章元数据和前台导航，不承担后台文件夹的职责。

### 5.2 顶部状态栏

顶部仅包含：

- 文章目录开关。
- 居中的保存状态：正在保存、所有更改已保存、离线且已存本地、保存失败。
- 预览。
- 更多操作。
- 发布或查看已发布状态。

页面不保留底部保存按钮。

### 5.3 中央写作画布

中央画布是页面主视觉。正文行宽控制在约 34 至 38 个中文字符。标题、段落、引用、代码、表格和图片尽量复用前台主题的排版语义。

编辑控件使用后台 UI 字体。正文使用当前主题的正文与标题字体。后台不是前台页面的复制品，但写作者应能在写作时感受到文章成形。

### 5.4 文章设置抽屉

下列字段从正文流中移到右侧文章设置抽屉：

- slug
- 内容类型
- 分类
- 摘要
- 封面
- 发生时间
- 可见性
- 归档和删除等低频操作

标题与正文继续留在画布内。抽屉关闭后焦点返回触发按钮。

### 5.5 发布检查面板

发布按钮打开右侧发布面板，不直接发布。面板包含：

- 当前站点主题下的桌面与移动预览入口。
- 阻断项：标题、slug、正文和有效可见性。
- 提醒项：摘要、分类、封面和发生时间。
- 最终动作，根据可见性写成“发布为公开文章”或“发布为不列出”。

发布成功后保留当前编辑位置，只更新顶部状态。撤回和归档仍是显式操作。第一版不支持定时发布。

## 6. 编辑器与基础组件

### 6.1 Milkdown

保留 Milkdown 作为文档编辑内核。它继续负责 WYSIWYG 编辑、Markdown 序列化、GFM、撤销历史和光标行为。

在现有封装上增加：

- `/` 插入菜单：标题、列表、引用、代码、分隔线和图片。
- 选区浮动工具条。
- 链接编辑，快捷键为 `Cmd/Ctrl + K`。
- 图片节点、上传进度、失败状态与重试。
- 空行上的轻量 `/` 提示。
- 清晰但不干扰的焦点、选区和占位状态。

编辑器对外仍只暴露 Markdown，不让 ProseMirror 文档结构泄漏到业务层。

### 6.2 Reka UI

使用 Reka UI 作为无样式交互基础。它负责弹层、菜单、对话框、焦点管理、键盘行为和无障碍语义。Alive 自己控制全部视觉样式。

后台在 Reka UI 之上封装薄组件：Button、IconButton、Menu、Popover、Dialog、Field、Toast、Tooltip 和必要的抽屉容器。业务页面不直接复制焦点与弹层逻辑。

官方资料：

- <https://www.reka-ui.com/docs/overview/introduction>
- <https://reka-ui.com/docs/guides/styling>

## 7. 自动保存与草稿模型

### 7.1 不完整草稿

服务端必须允许草稿处于不完整状态。点击“新文章”后立即创建草稿并返回文章 ID。草稿的标题、slug 和正文可以为空。

完整性校验从创建和普通保存阶段移到发布阶段。发布时必须满足：

- 标题非空且长度有效。
- slug 非空、格式有效且不冲突。
- 正文非空。
- 可见性为允许值。

slug 在输入标题后生成建议。用户手动修改过 slug 后，标题变化不再自动覆盖它。

### 7.2 保存节奏

1. 编辑变化先写入本地恢复缓存。
2. 停止输入约 1 秒后提交服务端保存。
3. 切换文章、打开预览和打开发布面板前强制完成保存。
4. `Cmd/Ctrl + S` 立即提交保存并显示明确反馈。
5. 同一时间每篇文章最多有一个进行中的保存请求，后续变化合并到下一次保存。

### 7.3 并发保护

文章增加轻量修订版本。客户端更新时携带已读取的版本，服务端只接受当前版本的更新并返回新版本。

如果旧标签页尝试覆盖新版本，服务端返回冲突。客户端保留本地内容并提供三个动作：

- 使用服务端版本。
- 使用当前本地版本覆盖。
- 将本地内容另存为恢复草稿。

系统不自动合并两份 Markdown。

### 7.4 本地恢复

本地恢复缓存使用适合结构化和较大内容的浏览器存储，不只依赖内存。缓存至少保存文章 ID、正文、字段变化、服务端版本和本地更新时间。

网络中断时允许继续写作，状态显示“离线，本地已保存”。恢复网络后自动同步。关闭页面后重新打开时，系统比较本地版本与服务端版本，不静默丢弃较新的本地内容。

## 8. 媒体流程

第一版只提供就地上传与当前文章内复用：

- 将图片拖入正文。
- 从剪贴板粘贴图片。
- 通过 `/图片` 选择文件。
- 封面使用同一上传能力，不再要求手填 URL。
- 上传后可以设置替代文本、图注和展示宽度。
- 当前文章已上传图片可以再次选择。

图片插入后立即显示本地预览和上传进度。上传成功后，编辑器将本地占位替换为正式媒体 URL，再进入 Markdown 保存。

上传失败只影响该图片节点，不阻断正文保存。失败节点保留本地预览、错误说明和重试入口。切换文章前，本地恢复缓存记录未完成上传状态。

第一版不提供全站媒体搜索、重复检测、批量整理和自动清理。

## 9. 主题系统

### 9.1 主题规则

主题是后台与前台共享的站点视觉配置，不是散落的 CSS 覆盖。

每个主题至少定义：

- 页面纸张与分层表面。
- 主文字、正文、弱文字和标题文字。
- 普通边线与强边线。
- 强调色、悬停色、危险色和焦点色。
- 正文字体、标题字体、界面字体和等宽字体。
- 图片阴影、代码块、引用和选中态。
- 必要的明暗模式声明。

### 9.2 预览与全站生效

点击主题只修改当前后台预览。写作画布和后台 UI 立即应用该主题。

只有点击“设为站点默认”后，服务端才保存默认主题标识。前台 SSR 使用站点默认主题。访客没有个人选择时跟随站点默认；已有本地偏好时继续使用个人偏好。

已打开的前台文章不通过实时推送突然切换主题。刷新或下一次导航时采用新默认。

### 9.3 初始主题

#### 纸墨

暖纸、近黑墨色、朱砂强调，强调中文纸本阅读。

#### 灯下

深色纸面、暖灰正文、提亮朱砂，服务夜间阅读。

#### Codex Lavender

参考用户当前 Codex 截图：

- 雾白正文纸面。
- 极浅冷灰侧栏。
- 淡紫选中背景。
- 薰衣草紫交互强调。
- 低对比冷紫边线。
- 标题使用更深的葡萄紫。
- 正文采用已确认的 B 版“薰衣草墨”，保持明显紫色体系，不退回中性灰。

主题名是 Alive 内部名称，不依赖 Codex 产品组件或运行时资源。

## 10. 模块边界

后台前端按职责拆分：

- `ArticleDirectory`：搜索、最近文章、状态分组、切换文章和未同步状态。
- `WritingWorkspace`：顶部状态栏、中央画布和目录收起布局。
- `MarkdownEditor`：编辑器内核与 Markdown 输出。
- `SaveCoordinator`：本地缓存、自动保存、重试、版本冲突和切换前刷新。
- `ArticleSettings`：文章元数据编辑。
- `PublishPanel`：预览、校验、提醒、发布与撤回。
- `ThemePicker`：主题预览、站点默认保存和主题状态。
- `MediaUploader`：文件接收、上传、进度、失败重试和当前文章内复用。

后端需要增加：

- 不完整草稿与发布阶段校验。
- 文章修订版本与冲突响应。
- 站点默认主题设置。
- 媒体上传和媒体记录。

各模块通过明确状态和 API 通信。编辑器不负责保存策略，目录不负责文章校验，主题选择器不直接操作前台页面。

## 11. 错误处理

- 自动保存失败：保留本地缓存，显示失败状态，退避重试并提供立即重试。
- 离线：继续写作，本地保存，目录显示未同步标记。
- 认证失效：暂停服务端同步，保留本地内容，引导重新登录，登录后恢复同步。
- 版本冲突：不覆盖、不自动合并，保留两份内容供选择。
- 图片失败：局部失败，不阻断正文保存。
- 主题保存失败：后台临时预览保持，明确提示前台默认主题没有改变。
- 发布校验失败：错误定位到具体字段，发布面板保持打开。
- 发布请求失败：文章仍是草稿，编辑内容和当前位置不变。
- 删除：继续使用明确二次确认。删除能力没有恢复接口时，不提供快速批量删除。

## 12. 响应式策略

- 桌面宽屏：固定文章目录与中央画布。
- 中等宽度：目录缩窄，设置与发布面板覆盖画布右侧。
- iPad 横屏：保留完整写作能力。
- iPad 竖屏：文章目录改为抽屉。
- 手机：默认只显示画布，目录、设置和发布检查使用全屏抽屉。

手机保留查看、文字修改、图片上传、设置调整和发布能力，但不把复杂长文编辑作为主要体验。浮动工具条在手机上简化，触摸目标不小于可用尺寸。

## 13. 无障碍与键盘

- `/` 打开插入菜单，方向键浏览，Enter 选择，Esc 关闭。
- `Cmd/Ctrl + K` 编辑链接。
- `Cmd/Ctrl + S` 立即保存。
- Tab 可以遍历目录、顶部操作、抽屉和发布检查。
- 弹层关闭后焦点返回触发位置。
- 保存状态使用可感知文本，不只依赖颜色和动画。
- 三套主题的正文、弱文字、控件、焦点和错误色都满足相应对比度要求。
- 支持 `prefers-reduced-motion`，不以动画作为唯一状态提示。

## 14. 验收与测试

### 14.1 单元测试

- 自动保存防抖、强制刷新和请求合并。
- slug 自动建议与手动修改保护。
- 发布阻断项和提醒项。
- 主题默认值、后台预览和访客偏好优先级。
- 修订版本冲突处理。
- 本地恢复版本比较。

### 14.2 组件测试

- 插入菜单、选区工具条、链接编辑和键盘导航。
- 文章目录切换与未同步标记。
- 设置抽屉和发布面板的焦点管理。
- 图片拖放、粘贴、进度、失败和重试。
- 保存状态的完整状态机。

### 14.3 集成测试

- 创建空白草稿、逐步保存、关闭后恢复并发布。
- 离线编辑后恢复同步。
- 多标签页版本冲突。
- 认证失效后重新登录并继续同步。
- 上传图片、保存 Markdown、重新打开文章。
- 保存站点默认主题后，前台 SSR 使用新默认。
- 访客已有本地主题时不被站点默认覆盖。

### 14.4 浏览器与视觉验收

每套主题分别检查：

- 后台文章目录、中央画布、设置抽屉和发布面板。
- 前台文章详情。
- 桌面宽屏、常规笔记本、iPad 横竖屏和 375px 手机宽度。
- 长标题、超长 slug、中英文混排、代码块、表格、大图和长图注。
- 加载、空状态、保存失败、离线、冲突和发布成功状态。

最终必须在真实浏览器中截图核对，不能仅凭构建通过或组件测试判断视觉完成。

## 15. 实施边界

这项工作跨越后台应用壳、编辑器、自动保存、文章领域规则、站点设置和媒体上传，应按依赖拆成实施阶段。设计确认后再编写独立实施计划。本设计文档不授权在同一阶段同时完成所有后续媒体管理、搜索和站点功能。
