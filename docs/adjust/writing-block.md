# Alive 调整实施计划

请按照以下 Phase 顺序执行，不要一次性完成全部需求。

原则：

- 每个 Phase 完成后先自检，再进入下一阶段。
- 不要进行与当前 Phase 无关的大规模重构。
- 如果发现后续 Phase 会依赖当前阶段的结构调整，可以做必要预留，但不要提前实现完整功能。
- 每个 Phase 完成后输出：
  - 修改文件
  - 主要改动
  - 接口 / 类型变化
  - 已验证内容
  - 尚未处理的问题

---

# Phase 1：数据结构、状态与功能正确性

这一阶段优先处理会影响实际使用的功能问题。

暂时不要重点调整视觉样式和动画。

## 1. 发生时间改为可选

检查前后台实现。

完成：

- 移除前端「发生时间」必填校验。
- 检查后端 DTO / 参数校验。
- 如果后端当前要求必填，同步改为可选。
- 检查数据库字段是否允许为空。
- 如果数据库暂时不能直接为空，分析是否需要迁移。
- 所有展示位置正确处理空时间。

保证不会出现：

- `Invalid Date`
- `undefined`
- `null`
- 空时间占位
- 多余分隔符

---

## 2. 片语移除 slug 依赖

完整检查片语创建、编辑、展示流程中对 `slug` 的依赖。

完成：

- 删除后台片语编辑表单中的 slug 输入。
- 删除相关必填校验。
- 修改前端 TypeScript 类型。
- 修改创建 / 编辑接口参数。
- 检查后端 request / service / repository 是否依赖 slug。
- 片语创建和发布不再依赖 slug。

如果数据库仍保留 slug：

- 本阶段可以暂时保留数据库字段。
- 不要求为了移除 slug 单独进行数据库迁移。
- 但业务逻辑不能继续依赖 slug。

同时检查前台是否还通过 slug 跳转片语详情。

---

## 3. 修复片语发布后的状态问题

当前问题：

1. 发布片语后左侧列表不会立即刷新。
2. 发布成功后点击「写片语」无法进入新建状态。
3. 无法连续发布多篇片语。

重点检查：

- 当前选中的片语 ID
- create / edit 状态
- 表单状态
- 列表刷新逻辑
- 发布接口完成后的状态同步
- query cache / store / composable
- reset 逻辑

目标流程：

```text
新建片语
↓
填写内容
↓
发布
↓
发布成功
↓
刷新左侧列表
↓
列表出现刚发布的片语
↓
点击「写片语」
↓
进入新的空白表单
↓
继续创建下一篇
```

禁止通过：

```text
window.location.reload()
```

或者其他整页刷新方式解决。

---

## 4. 左侧列表增加删除功能

写作区左侧列表增加删除能力。

完成：

- 每条内容提供删除入口。
- 删除前弹出确认。
- 优先复用现有确认组件。
- 删除成功后立即更新列表。

如果删除的是当前正在编辑的内容：

- 清理当前 selected id。
- 清空编辑状态。
- 切换到合理的默认状态。

不要出现：

- 删除后右侧仍显示已删除内容。
- 删除后再次保存导致异常。
- 删除后列表状态和编辑区状态不一致。

---

## 5. 日志移除无用字段

日志 / 文章编辑中移除：

- 封面
- 摘要
- 图片或视频

检查完整链路：

```text
UI
↓
Form State
↓
Validation
↓
Request Type
↓
API Payload
↓
Backend DTO
↓
Save Logic
```

如果数据库仍然存在对应字段，可以暂时保留。

本阶段不要求做数据库删除迁移。

# Phase 2：后台编辑体验与布局

这一阶段主要调整后台写作体验。

不要修改前台视觉。

## 1. 清理后台说明性文案

检查后台页面。

删除：

- 产品设计解释
- 教程式说明
- 不影响用户操作的信息
- 对状态含义进行长篇解释的文案

例如删除：

> 草稿是待办队列，归档不是。这里把两者分开。

保留：

- 字段名称
- 必要提示
- 操作反馈
- 错误信息
- 状态名称

目标：

后台整体更加干净、克制。

---

## 2. 写作区左侧列表调整

调整左侧列表：

### item-cursor 间距

增加文字与 `item-cursor` 之间的距离。

只调整：

- padding
- margin
- gap

不要破坏 cursor 本身逻辑。

---

## 3. 片语左侧列表展示内容

目前如果显示标题，改成显示片语正文内容。

要求：

- 每项展示正文摘要。
- 不显示片语标题。
- 限制列表项高度。
- 内容过长时使用渐变遮罩隐藏。

不要使用普通：

```text
...
```

作为主要截断方案。

目标效果类似：

```text
这是今天路过海边时突然想到的
一句话，也许很多事情其实……
          ↓ 渐隐
```

---

## 4. 日志编辑器放大

优化日志写作区域：

- 编辑器整体高度增加。
- 编辑器正文宽度更加适合长篇写作。
- 正文字号增加。
- 行高增加。
- 段落间距优化。
- 减少无意义留白。

目标：

长时间写作更加舒适。

---

## 5. 片语编辑改为左右布局

PC：

```text
┌──────────────────────┬───────────┐
│                      │           │
│      片语内容         │  片语设置  │
│                      │           │
│        约 70%         │   约 30%   │
│                      │           │
└──────────────────────┴───────────┘
```

左侧：

- 正文
- 主要编辑区域

右侧：

- 发布时间
- 状态
- 其他设置

移动端：

保持纵向布局。

不要在移动端强制使用 7:3。

---

## 6. 影像编辑改为左右布局

PC：

```text
┌───────────────────┬───────────────────┐
│                   │                   │
│       画面         │       文案         │
│                   │                   │
└───────────────────┴───────────────────┘
```

比例根据内容合理设计。

### 未上传媒体

画面区域需要：

- 默认宽度
- 默认高度
- 稳定占位

不能塌缩。

### 已上传媒体

根据媒体比例：

- 自适应宽高
- 保持原始宽高比
- 不拉伸
- 设置合理 max-width / max-height

超宽图和超高图都要正常。

移动端恢复纵向布局。

---

## 7. 为 OSS 图片粘贴能力预留结构

本阶段不实现真实 OSS 上传。

检查当前编辑器架构是否可以支持未来：

```text
粘贴图片
↓
生成临时图片
↓
编辑器预览
↓
发布
↓
上传 OSS
↓
取得正式 URL
↓
替换正文临时 URL
↓
保存
```

如果当前结构存在明显障碍，可以适当调整。

需要说明：

- 当前编辑器图片节点如何存储。
- 粘贴图片事件在哪里接入。
- 后续 OSS 上传适合在哪一层实现。
- 发布前 URL 替换适合在哪里实现。

不要在没有 OSS 配置的情况下模拟真实上传。

# Phase 3：前台文章阅读体验

这一阶段专门调整文章。

避免同时修改片语视觉。

## 1. 文章详情排版优化

调整：

### 标题

字号适当减小。

### 正文

字号适当增加。

同时调整：

- line-height
- paragraph spacing
- heading spacing
- content width
- 图片上下间距
- 引用块
- 列表
- code block（如果存在）

目标：

从：

> 网站文章详情页

向：

> 一本书中的正文阅读页

靠近。

重点是「长时间阅读舒服」。

---

## 2. 文章列表支持创建时间排序

增加：

- 创建时间正序
- 创建时间倒序

优先复用现有：

- query 参数
- sort store
- select
- composable
- API sort 参数

如果当前 API 不支持排序，再判断：

- 前端排序是否足够
- 或是否应该补后端排序

如果存在分页，禁止只对当前页数据进行前端排序后假装实现全局排序。

---

## 3. 移除文章时间线视觉

删除文章列表当前的：

- 时间轴
- 节点
- 连线
- 其他强时间线表达

重新整理列表。

视觉目标：

```text
Chapter 01
标题……

Chapter 02
标题……

Chapter 03
标题……
```

不要求真的显示 `Chapter`。

核心感觉：

> 像在浏览一本个人文集的目录。

突出：

- 顺序
- 篇目
- 留白
- 阅读感

弱化：

- 卡片感
- 新闻列表感
- 时间线感

---

- 分享

# Phase 5：视觉细节与 GSAP 动画

功能稳定后再做动画。

所有动画保持：

- 克制
- 自然
- 不抢内容
- 不影响滚动性能

---

## 1. 照片墙毛玻璃卡片

卡片调整为毛玻璃风格。

包括：

- 半透明背景
- backdrop-filter
- 柔和边框
- 轻阴影

需要注意：

- 背景图片较亮时文字仍然可读。
- 背景较暗时不要过度发灰。
- 不要使用太重的 blur。

---

## 2. Hover 暗示可点击

PC hover 时可以使用：

- translateY
- scale
- shadow
- opacity
- glass highlight
- cursor

目标：

用户自然意识到：

> 这个卡片可以点。

不要增加「点击查看」按钮。

Hover 动画不要过强。

---

## 3. 片语滚动进入 / 离开动画

片语内容从页面底部进入视口：

建议：

```text
opacity: 0 → 1
y: 20~40px → 0
```

离开时自然反向。

要求：

- 使用 GSAP。
- 如果使用 ScrollTrigger，正确注册。
- 组件卸载时 kill。
- 路由切换时清理。
- 不重复初始化。
- 不因为动画修改造成页面布局抖动。

如果项目已有 GSAP composable，优先复用。

---

## 4. 弹窗打开动画

弹窗：

```text
overlay:
opacity 0 → 1

content:
opacity 0 → 1
scale 0.97 → 1
或者
y 20 → 0
```

动画保持轻微。

---

## 5. 弹窗关闭动画

关闭流程必须是：

```text
点击关闭
↓
播放 GSAP leave
↓
动画结束
↓
隐藏 / unmount
```

不能：

```text
点击关闭
↓
立即 v-if = false
↓
DOM 消失
↓
动画无法播放
```

检查 ESC、点击遮罩、关闭按钮是否统一走同一套关闭逻辑。

---
