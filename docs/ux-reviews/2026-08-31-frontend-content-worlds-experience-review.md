# Alive 前台「内容世界」体验评审

日期：2026-08-31  
评审方式：本地 Nuxt 前台真实访问，桌面默认视口 + 375px 移动视口  
范围：首页、日志列表与详情、片语、影像、标签、主题入口、移动端布局

## 结论先行

前台的日志阅读体验已经有明确的编辑型气质：窄内容列、安静的排版、按年份组织的时间线。问题在于“内容世界”目前只在路由层存在，尚未成为访客可以理解和浏览的站点结构。当前公开数据只有日志时，首页和导航不会解释片语、影像在哪里，未开放世界也没有给出状态语义。

优先级：

1. P1：首页实际只展示日志，访客看不到内容世界的入口或状态说明。
2. P1：全局页头没有世界导航，所有世界页面只能依靠直接 URL 或页脚分类进入。
3. P1：片语与影像空状态没有解释“尚未开放”和“暂无内容”的区别。
4. P2：页面整体内容列过窄，右侧留白过大，首页和详情页的首屏信息密度偏低。
5. P2：主题切换入口的可访问名称和视觉识别度不足，DOM 中只显示当前主题文字及无语义图标文本。
6. P2：前台存在 `/tags` 入口缺失的情况，直接访问会进入 404 页面；只有 `/tags/:slug` 路由可用。

## 1. 首页混合流

### 已验证体验

- 首页可以正常 SSR 渲染。
- 当前首屏只显示“日志”区域，按年份分组展示文章。
- 每条日志显示标题、摘要（有摘要时）、日期和“日志”标签。
- 页脚只有版权信息；有分类时才显示分类导航。
- 375px 下日志列表没有明显横向溢出。

### 问题

- 代码层面的混合首页目前只请求日志和片语；影像没有进入首页混合流。
- 当前片语和影像没有公开数据时，首页完全没有“世界”的概念，访客会误以为 Alive 只有日志。
- 页头只有 Alive 和主题切换，没有日志、片语、影像的浏览入口。
- 内容列明显偏窄，右侧留下大片空白，首页首屏的可浏览内容少于视口承载能力。

### 建议

- 首页保留日志作为主叙事，但增加轻量的世界入口或世界索引，不要依赖页脚分类承担站点导航。
- 混合流按既定规则增加片语和最近影像区块；若某世界未开放，显示安静的状态提示而不是静默消失。
- 页头加入世界导航，至少展示已开放世界；未开放世界可不展示，但管理状态变化后应自动反映。
- 维持窄栏阅读气质，同时在桌面端把内容列适度放宽，或使用右侧留白承载世界索引/最近更新，而不是完全空置。

## 2. 日志列表与详情

### 已验证体验

- `/` 首页日志条目可进入 `/journal/:slug`。
- 详情页展示标题、发布日期、世界标签、字数、正文和上下篇导航。
- 正文排版适合长文阅读，标题、段落、导航层级清楚。
- 日志保留时间概念，首页按年份分组，符合日志世界定位。

### 问题

- 详情页顶部没有明显“返回日志列表”或世界导航，读者完成阅读后只能依赖上下篇、品牌返回或浏览器返回。
- 页面顶部和正文列都很靠左，长篇阅读时右侧空白过大，桌面利用率偏低。
- 文章的“日志”标签更像普通元数据，世界身份没有成为可点击的浏览入口。
- 主题切换在详情页的视觉存在感很弱，当前主题的语义主要依赖隐藏在控件中的文字。

### 建议

- 在详情页标题附近增加低干扰的“日志”返回入口，形成“世界 → 文章”的路径感。
- 将世界标签做成可点击入口，返回该世界列表，而不是只作为静态文本。
- 桌面端适度增加正文最大宽度，保留编辑感但减少无效留白。
- 文章导航、页脚和世界入口使用同一套间距与链接样式，减少页面末端的孤立感。

## 3. 片语世界

### 已验证体验

- `/sayings` 路由可正常打开。
- 页面标题为“片语”，文案明确强调“只展示内容本身”。
- 页面支持流式、纸片墙、一句模式的浏览器偏好逻辑。
- 当前无公开片语时，页面显示“还没有公开的片语”。

### 问题

- 空状态只说明没有公开内容，没有说明片语世界当前是未开放还是已经开放但为空。
- 页面没有从全局导航进入的入口，访客无法发现三种浏览方式的存在。
- 当内容为空时，浏览方式切换器仍然是页面主要视觉元素，显得像不可验证的功能承诺。
- 页头重复出现 kicker“片语”和一级标题“片语”，信息价值偏低。

### 建议

- 根据世界状态区分文案：未开放、已开放但暂无内容、已有内容。
- 空状态时可以保留浏览方式说明，但将切换器弱化或延后到有内容时显示。
- 在有内容时，为每条片语提供稳定的永久链接和复制动作；片语不需要重新引入时间轴。
- 保留轻量语气，但减少重复标题，让句子内容成为页面视觉主角。

## 4. 影像世界

### 已验证体验

- `/videos` 路由可正常打开。
- 页面标题和世界标签显示为“影像”。
- 当前无公开影像时，页面显示“还没有公开的影像”。
- 影像列表和详情路由已存在于前台代码结构中。

### 问题

- 当前空状态与片语相同，只说没有公开内容，没有说明世界状态。
- 影像世界没有全局入口，且首页混合流不会出现影像区块。
- 在没有内容时，访客无法判断影像功能是暂未开放、等待上传，还是单纯数据为空。

### 建议

- 引入世界状态文案，避免把未开放误读成空数据。
- 影像列表页应在有内容时展示封面、时长、标题和播放入口；首页只展示最近少量内容，避免抢走日志主叙事。
- 影像详情页应在播放器附近提供返回影像世界的入口。

## 5. 标签与分类入口

### 已验证体验

- `/tags/:slug` 可以进入标签详情逻辑。
- 不存在的标签会显示“标签不存在”的中文 404 状态。
- 直接访问 `/tags` 时会进入 Nuxt 404，因为当前没有标签索引页。

### 问题

- 如果产品把标签当作跨世界聚合入口，缺少 `/tags` 索引会让访客没有发现路径。
- 标签页面的错误态在开发模式下会叠加 Nuxt DevTools 错误面板，普通访客体验会被内部调试信息干扰。
- 目前首页和页脚没有提供标签入口，跨世界发现依赖用户已经知道 URL。

### 建议

- 明确标签产品定位：需要索引就补 `/tags`，不需要索引就不要在任何地方暗示存在标签首页。
- 生产构建必须隐藏 Nuxt DevTools 和详细错误叠层。
- 如果标签是世界之间的共同入口，可在标签详情页增加“来自日志 / 片语 / 影像”的世界标识。

## 6. 主题与全局页头

### 已验证体验

- 页头显示 Alive 品牌，点击返回首页。
- 主题切换控件显示当前主题“薰衣草”。
- 页面主体、页脚和详情页沿用一致的纸张感和低对比度色彩。

### 问题

- 主题控件在可访问树中的语义不够清晰，主要可见文本是当前主题，控件的操作意图不够明显。
- 页头缺少世界导航，主题成为唯一的右侧操作，结构上显得空。
- 整体对比度偏低，尤其在大面积留白中，链接和元数据容易退到背景里。

### 建议

- 为主题切换提供明确按钮名称，例如“切换主题，当前为薰衣草”。
- 页头右侧可以放世界索引或低干扰导航，再保留主题切换作为次级操作。
- 不需要大幅提高整体颜色饱和度，只需提高链接、日期、世界标签的层级对比。

## 7. 移动端

### 已验证体验

- 375px 下首页日志按年份和文章顺序正常显示。
- 没有发现明显横向滚动或标题截断。
- 窄屏保留了安静的单列阅读方式。

### 问题

- 移动端没有额外的世界导航，访客仍然只能看到日志。
- 首页首屏信息量偏少，向下滚动前无法理解站点还有哪些内容类型。
- 详情页长文阅读可用，但缺少显式返回世界入口时，移动端更依赖浏览器返回手势。

### 建议

- 在移动页头增加可展开的世界菜单，已开放世界保持稳定顺序。
- 首页首屏用一行轻量索引提示“日志 / 片语 / 影像”，不要做成大型导航栏。
- 详情页底部保留上下篇，同时增加返回当前世界的动作。

## 8. 建议的前台修复顺序

### 第一阶段：让世界可被发现

1. 全局页头增加已开放世界导航。
2. 首页按世界状态呈现日志、片语、影像的混合结构。
3. 片语和影像空状态区分“未开放”和“暂无内容”。
4. 统一详情页的世界返回入口。

### 第二阶段：修复跨世界发现

1. 决定是否需要 `/tags` 标签索引页。
2. 首页或页头提供标签/世界索引的发现路径。
3. 世界标签、分类链接、详情页返回动作统一链接样式。

### 第三阶段：视觉与可访问性精修

1. 调整桌面内容列宽度和右侧留白使用方式。
2. 提高日期、世界标签、链接的对比度层级。
3. 为主题切换补充明确的按钮语义。
4. 对首页、详情、片语、影像做一次 375px 长文本和空状态检查。

## 已确认不应在本轮扩大范围的内容

- 不因为前台缺少世界导航，就提前实现尚未开放世界的完整内容生产能力。
- 不重新引入片语的时间轴表达。
- 不为了填充桌面空白加入装饰性大图或营销 Hero。
- 不把 Nuxt 开发错误面板当作正式产品错误页设计。
